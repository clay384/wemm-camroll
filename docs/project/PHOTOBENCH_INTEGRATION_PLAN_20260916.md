## 3. 必须对齐的指标

| 指标 | 当前口径 | CamRoll 接入所需 |
|---|---|---|
| 正确/部分正确/错误 | 最终轮 Judge=2/1/0；按 qa_id 一题一票 | 保存完整回答及多轮记录，同一 Judge 与提示词 |
| 质量均分 | 有效评分之和 / 有效评分数，范围 0–2 | 无效评分单列，不能冒充 0 分或静默丢失 |
| 完全准确率 | 2 分数 / 有效评分数 | 同时列有效数/计划 100 题 |
| 核心准确率 | (1 分数+2 分数) / 有效评分数 | 保留 1 分与 2 分分布 |
| 媒体 P/R/F1 | 显式最终交付与 GT 比较；逐题计算再平均 | 明确最终交付 IDs，映射为原始文件标识 |
| 工具候选命中 | 独立候选集合与 GT 比较 | 记录实际返回给 Agent 的候选，不用全库或 GT 反补 |
| 任务判断 | answer/refuse/clarify 与每轮标注比较 | 100 题有 111 轮，不用 100 作该指标分母 |
| 证据支持 | 独立图片 Judge=0/1/2；默认开关关闭 | 同样开关、同样图片处理、同样提示词；非质量评分替代 |
| 步数内完成 | 终态、答案存在、未因预算/超时等终止 | 规范化停止原因，合法澄清/拒答要保留语义 |
| 动作/JSON 解析 | 指定 Agent/Recovery 输出的合法动作解析 | CamRoll 原生 tool_calls 单独校验，不能用正常文本答案充当解析失败 |
| Agent 单题耗时 | 每题全部对话轮的 Agent 时间，不含 Judge；并发负载下含排队 | 请求级计时、队列等待、开始结束时间 |
| 并发吞吐折算时延 | Agent 阶段实际墙钟 / 题数 | 不等于平均单题时延，不从累计调用耗时推算 |
| 单题端到端耗时 | Agent + Judge 排队 + Judge 执行 | 单列 mean/P50/P95/max |
| 全链路时间（不含 Judge） | identity_seed 开始至全部 Agent 完成；不含模型部署及相册创建 | 在 CamRoll 输入/身份准备的对应边界开始，保存实际 Agent 结束时间 |
| 模型部署耗时 | 独立阶段 | 复用既有 WeMM 标为复用/不适用，不能声称冷启动为 0 |
| 建库阶段 | 导入、预处理、caption、事件、embedding 等墙钟及调用耗时 | 补阶段 span、逐图调用、成功/失败/缓存命中数 |
| 工具性能 | 调用次数、成功率、P50/P95/max | 工具起止计时，关联所属模型轮和调用 ID |
| 模型性能 | 每次 TTFT、耗时、输入/输出 token、token/s、流式状态、上下文分布 | 为主 Agent 每次调用埋点；工具内部 VLM 与最终复核分角色记录 |
| 资源 | 进程显存、整卡显存、利用率、功耗、温度、RAM、采样数与分阶段峰值 | 采 `.100` WeMM 指定 GPU/PID；CamRoll CPU/RAM；云端 GPU 不可见则 N/A |
| 成本 | 现有 CamRoll 云预算可扩展展示 | 生成、建库、Judge、重试分别统计；不重置既有预算 |

正常完整运行中，媒体指标排除 19 道 unanswerable，剩余 81 道；无 GT、映射失败、执行失败等必须额外报告实际分母。现有异常返回路径可能缺少 typed counts，不能仅看宏平均就认定 81 题都已计入。接入验证要专门覆盖失败和零交付，必要时增加覆盖率/固定 100 题完成情况的补充指标，保持与历史官方口径区分。

宏平均 F1 是各题 F1 的平均，不是宏平均 P、R 再求一次 F1。微平均也有独立字段，不能把两者混用。WeMM 原实验 Hit@K 可保留为额外诊断，但不能替换这里的最终交付 P/R/F1。

并发阶段相互重叠，不能将各次调用耗时累加当作墙钟，不能将整个 Judge 累计耗时从并发总墙钟中直接相减。旧记录没有实际 Agent 阶段边界时存在估算回退，应标记而不用于严格速度排名。

Sentrix 的人脸检测、CLIP、事件聚类、L3 证据账本与 CamRoll 并非一一对应。展示共同阶段和各自内部阶段；没有的阶段/数据写“不适用/未记录”，不伪造为 0 或 100%。云端 Qwen 不可观测显存，不能据本地 WeMM 显存宣称整套系统比纯本地系统省显存。

M1 结构化交付是协议修改，可能影响输出；需保留版本并在非正式测试题上验证，不能按 100 题 GT 调整交付列表。M2/M4 的最终图片复核不应被当作 M1 的必要接入条件；先固定 M1 主结果，其他配置独立 run。

TTFT 目前不能从 HTTP/SSE 的第一条 status 事件获得；那不是模型首 token。CamRoll 虽有云流式收集代码，但主 Agent 默认非流式，需增加真实采集，或者诚实保留 TTFT 未记录。token/s 的分母要与编排器已有轨迹定义核对后固定。

### 身份与可信元数据：输入公平性和能力改动要区分

Sentrix full 会上传 8 张带名字/别名/角色的参考照，并导入 6 条家庭关系。CamRoll 当前只接受可选的一张参考照，而且提示词明确不依据它推断姓名；没有等价的八人注册与匹配。

- 建议增加独立身份资料表、关系表和合法取用接口，并把同一份资料提供给 Agent/看图环节。是否实际匹配成功由模型与证据决定，不能把姓名映射写成已验证识别能力。
- 可用已有 Qwen 做带命名参考照的对照看图接入，不必为了兼容接口先新增人脸模型；但这是新的能力实现，需单独验证，可能增加成本与时延。
- 日期/位置来源要核实 Sentrix 实際使用的 EXIF/可信输入。CamRoll 当前读取日期、可接收 location/people，但不等于已经自动获得 GPS 与可信姓名。
- 若先测现状，也可以让系统在身份题上如实不能确认；报告必须说明参考资料未被利用的能力差距。不能删除身份题以提高总分。
- 从 QA 答案、人工事件总结、逐图人物 GT 推导姓名/地点再写入索引，会改变输入条件，不属于单纯接入。

WeMM encoder、worker、原预处理、模型配置和旧库均无需为本接入修改。新相册、快照及结果必须独立保存。

## 5. Judge：优先继续用 Doubao

已抽查的 100 题 full 历史记录使用 `doubao-seed-2.0-lite`。Judge 是独立 OpenAI-compatible 调用，读取题目、参考答案、模型回答和对话，不依赖被测系统必须是 Sentrix。因此可以继续让 `.153` 编排器用已有 Doubao 配置评 CamRoll，密钥留在原受限配置中，不必复制给 `.100`。

当前自定义回答质量提示词 SHA256：`ef6abfa4c8e2dda996c8ac8cacec1804f03b77924dbdb4bfb30622f9ed2dbc7c`，与抽查历史记录中的主要 system prompt 一致；部分历史请求另有一致性纠正版本。正式运行还应冻结完整提示词模板、任务判断规则、证据开关、参数和 Judge 返回的模型信息。

本次确认的是代码与历史可用性，没有发起新的 Doubao 请求。实施时先做少量文本、任务判断、可选图片评分接通检查；凭据/额度/网络是否仍可用以届时结果为准。

Qwen3.7-Flash 可作为备用 Judge，需配置独立 Judge 客户端/角色、预算与日志。如果改用 Qwen，应让待比较的旧回答也经同一 Qwen Judge 重评并保存为新的评分版本；不能直接比较“Qwen 评我们”和“Doubao 评别人”的分数。优先独立 Doubao 也可减少生成者兼任评判者的偏差。Judge 费用单列，不能假定原 CamRoll 预算已经包含其他提供商费用。

可选图片证据 Judge 当前从 Sentrix `/api/assets/{id}/file` 取图；CamRoll adapter 必须提供等价的图片获取方式。沿用同样的 896 边长/JPEG 处理与开关，才能比较该项。

## 7. 推荐实施顺序与验收

1. 冻结 355 图/100 题、8 人/6 关系、完整 Judge 设置、计分代码、M1 版本、并发与预算。选择要比较的具体历史 run。
2. 做 CamRoll adapter、媒体映射、真实多轮会话、结构化交付和性能埋点；加入身份资料接入，或明确第一版保留其能力差距。
3. 用 mock/独立样例验证单图、多图、零交付、未知 ID、澄清两轮、拒答、超时、重试、Judge 失败、快照隔离、并发预算与时间重叠。用历史结果回放核对新适配不会改变 Sentrix 评分。
4. 在独立目录用少量非正式样例验证建库、看图、Doubao、预览、轨迹与资源采样；不根据正式 100 题 GT 优化提示词。
5. 正式 cold full：模型可预先就绪，但照片/描述/索引使用全新相册，缓存不复用；记录原始媒体/身份输入准备至最后 Agent 完成。模型加载另列。性能若使用 334 图已有缓存只能标 warm/reuse。
6. 跑完整 100 题，共 111 轮，保留所有失败与无效 Judge，不静默换模型或挑题重跑。续跑与首次耗时分开记录。
7. 在同一 UI 展示质量、交付召回、工具召回、单题时延、吞吐、建库阶段、token、费用及资源；按题型和身份/时间等维度查看差异。旧结果保持不可覆盖。

正式完成标准：355 图输入与资产映射可追溯；全部 100 题有执行状态；11 道多轮真正共享上下文；19 道拒答题保留；评分有效数/错误数/缺失数明确；候选与交付独立；真实时延和资源采样有来源；可在同一计分版本下与选定 Sentrix run 逐题比较。

本文不要求先实现 ANN、视频、OCR 模型、重排或改写 WeMM。接入、可观测性、多轮协议属于第一阶段；身份匹配与策略提升应单独标版本，避免把评测接入和针对正式题集调优混为一体。
