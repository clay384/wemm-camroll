# W38Max 补测媒体绑定修正 v2

本版保留 [v1 的选题、模型、评分与固定分母](PHOTOBENCH_W38MAX_403_SUPPLEMENT_V1.md)，只修正补测适配器的媒体绑定。v1 复制快照后继续使用记录中的原相册绝对路径，与复制目录的 `assets` 安全边界不符，因此不能将其执行结果用于模型能力比较。旧记录、费用和审计必须保留。

## 正确绑定与运行前门槛

- `pinned_memory` 仅作字节级审计副本，不能当作可迁移的完整相册。
- 查询和看图使用原相册目录的只读 `Library`，核对原快照版本；不修改记录、原图片路径或冻结核心的目录安全检查。
- 创建付费客户端前，按真实 `Library.image_paths` 验证全部图片可用。每题构造 Agent 时再次核版本、目录、图片路径以及整个原相册的文件哈希；结束时复核原相册和父运行不变。
- 新请求 journal、run namespace、对话上下文与进程内查询缓存仍独立。原 `state.sqlite` 不被查询适配器写入。
- 原相册全文件哈希校验耗时纳入补测本地工作量，补测耗时不能与独立冷建库全链路耗时直接比较。
- 端到端回归保留真实 Backend、Library、Agent、图片工具和最终复核，仅替换云传输；测试必须观察到真实图片读取及两类视觉请求。只验证快照元数据或 FakeBackend 不足以通过此门槛。

## 无效记录与再次执行

报告通过独立 `evaluation/supplement-validity-audit.json` 注明实施有效性，不修改原 `run.json` 或其导出。`valid=false` 的补测在列表隐藏能力指标，详情保留故障证据与真实费用，并明确“不用于模型比较”。

修复本身不启动付费运行，也不删除旧 selection claim。再次运行必须有新的明确授权与独立 run、请求身份和审计记录，不能悄悄解除 claim、覆盖失败记录或伪装成原首跑。
